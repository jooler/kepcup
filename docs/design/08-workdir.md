# 08 工作目录（Workdir）

## 概念

- 工作目录（workdir）是用户选择的一个本地目录，是**用户的工作空间**。Bot 在其中拥有完整的代码编辑能力。它与任务的执行根目录（`cwd`，任务派出时确定，缺省即绑定的工作目录）是两个概念：workdir 是对话绑定的共享目录，cwd 是单次任务的执行根（D140-4：worktree 任务取隔离树为 cwd，见下文「worktree 隔离」）。
- 工作目录绑定到对话：项目组在项目详情页「概览」的工作目录选择器（单聊在右栏「配置」tab）中选择一个本地目录。一个对话同一时间最多绑定一个工作目录。
- 选定后，项目组的**所有成员**（或单聊的 Bot）都有该目录的读写权限；授权随成员关系自动成立，无需逐个授权。
- 新成员加入已绑定工作目录的项目组时，沟通里落一条系统消息「{name} 已加入项目组，获得工作目录「{label}」的读写权限」（沿用「工作目录已切换」的先例）。
- 用户要求 Bot 处理文件时，默认目录就是工作目录。
- Bot 的 workspace 仍然存在，退回为 Bot 私人的草稿区（临时脚本、中间产物），与工作目录区分。

## 实体

```text
Workdir
  id
  path
  name
  protect_rules      -- 禁止读取 / 写入的文件规则
  status             -- available | missing
  created_at, last_used_at

Conversation
  workdir_id         -- 当前绑定的工作目录，可为空
```

- 同一目录只对应一条 Workdir 记录，可被多个对话选用（对同一 conversationId 再选同路径时复用既有记录）。选择是**单步操作**：未绑定时点击选择器直接打开系统目录选择框，选完立即弹出「目录设置」（此时目录尚未确认、不显示「移除当前目录」，点保存才正式绑定并写入权限）；已绑定时点击条目直接打开「目录设置」调整权限或移除目录。
- 目录被移动或删除时标记为不可用，并在对话中提示用户重新选择。

## 选择与切换

- 首次绑定只在对话中落「工作目录已绑定为 X」一条系统消息；授权范围说明（项目组的所有成员或单聊 Bot 可读写、写入按租约串行、`.env` 等敏感文件默认不可读）属于对话配置信息，Bot 无需感知，不再发进消息列表，用户在「目录设置」中查看与调整。
- 切换或取消工作目录会在对话中产生一条系统消息（例如“工作目录已切换为 X”），Bot 可见。
- 有 Bot 正在执行时，不能切换或取消工作目录。
- 创建期引导：新建 Bot 的初始化访谈在首问作答后、首个响应 run 之前插入「工作目录」一问，可选「暂不设置」，之后随时用工作目录选择器手动绑定。新建项目组创建时不收集工作目录（保持点选即建），建好后在项目详情页「概览」绑定。见 [19-work-path-and-group-setup.md](19-work-path-and-group-setup.md)。

## 上下文注入

系统层增加工作目录信息：

- 工作目录路径与顶层目录结构摘要
- git 状态（如果是 git 仓库）
- 根目录的 `AGENTS.md` / `CLAUDE.md` 内容（与 Claude Code、Codex 的约定一致）

Bot 的文件工具以该工作目录为默认工作目录。

## 权限与保护

- 沙箱中工作目录的挂载方式见 [10-sandbox.md](10-sandbox.md#文件系统规则)。
- 默认保护规则：禁止读取 `.env*`、`*.pem`、`*.key` 等敏感文件；每个工作目录可以调整。
- Bot 默认只在工作目录与自己的 workspace 中工作；用户要求处理工作目录以外的文件时，经授权后可以访问和修改，见 [13-permissions.md](13-permissions.md)。
- `.git/config`、`.git/hooks` 在沙箱内不可写，防止 Bot 植入 git 钩子或篡改远程配置。
- **worktree 的精确例外（D140-4）**：隔离任务的 `git worktree add / remove` 由宿主在**沙箱外**执行，只写 `<git-common-dir>/worktrees/<name>/` 与 `<git-common-dir>/objects/`；`.git/config`、`.git/hooks` 与 `.git` 其余部分对沙箱仍不可写。`objects/info/alternates` 落在放行子树的残余风险见 [10 §worktree 双根](10-sandbox.md#worktree-双根d140-4-修订)（DEV-152）。
- git 远程操作（push / pull / fetch）以及 `git init`、`git remote add` 这类需要改写 git 配置的操作，由核心服务在沙箱外代为执行，**每次都需用户确认**。

## 并发：写入租约

> **D75 修订**：
> - 租约的适用面从 workdir 扩到 **workspace**（租约键 `ws:{botId}:{conversationId}`）。原先同一对话内的 workspace 并发写由串行 mailbox 兜底，D75 拆分后该兜底消失，改由租约承担：同一 workdir 同时最多一个写任务，只读任务不限（**D140-1 起改为多个共享写任务并存，见下**）。workspace 没有影子仓库检查点，故其写任务被取消时只列出文件工具写过的文件、**不提供整次回退**。
> - 写只发生在**写任务**里：对话轮与只读任务由网关硬拒一切写路径（`RUN_READ_ONLY`），不申请租约。写任务在启动前取执行根（workdir 或 workspace）的租约并**整个任务持有**（`pin`，与外部智能体的 run 同一语义），等租约期间不占调度名额。钉住的租约不能换成别的租约目标：cwd 是 workspace 的写任务去写 workdir（文件工具自动申请或 `acquire_workdir_write`），得到 `PATH_OUT_OF_SCOPE`（「本次执行整体持有 … 的写入租约，不能再写入其他租约目标」），需要改 workdir 应另派 cwd 为 workdir 的写任务；cwd 是 workdir 的写任务调 `acquire_workdir_write` 直接返回已持有。写任务写自己的 workspace 不需要租约，写授权范围内的外部路径按授权放行（`ensureWriteLease` 只在网关判定 `needs_lease`——即写 workdir——时才被调用）。下文「写入类工具自动申请」「`acquire_workdir_write`」的描述只对不钉住租约的执行（宿主伪身份等）原样成立。
> - **强制收回**让持有方写任务**失去写权限**（design 30 §5.1）：它的窗口当场收口（改动记录只含它自己的改动），之后它的一切写入（文件工具、命令的可写挂载、`acquire_workdir_write`、它的子代理）都以 `RUN_READ_ONLY`「写入租约已被用户收回」失败，不会再悄悄重新取得租约。一个 run 多次持有租约（非钉住的执行被收回后再写）时，改动记录跨窗口累积，整次回退撤销全部窗口；别人夹在两个窗口之间改过的文件按冲突处理（审查批 E，见 DEV-018）。
> - 同一 workdir 的第二个写任务在**任务层**排队（停在 submitted，任务卡与状态行显示「等写入租约（任务 … 持有）」），不在租约上等（**D140-1 起内置写任务不再这样排队，见下**）；对它「强制收回」无效，放行方式是取消持有方任务。强制收回只对租约层的等待（被非任务持有者挡住）出现（见 DEV-015）。
> - **D123 修订**：写任务的租约键升级为结构化写域键 `{root, patterns}`（`start_task.writes` 声明的 glob 集，`writes: true` = 整根即原语义）；冲突判定从「路径前缀重叠」细化为「根重叠 ∧ 写域（绝对化 glob 集）相交」，域不相交的写任务并行持有同一 workdir 的各自域租约。`LeaseService` 冲突谓词改为可注入（缺省仍为前缀规则，其余调用方零改动）；`waiting_lease` / FIFO / 让名额 / 强制收回语义不变。执行期按写域硬拒域外写入（`WRITE_OUT_OF_DOMAIN`）。详见 [59](59-parallel-tasks-and-coordination.md) §3。
>
> 见 [30 §5](30-supervisor-and-tasks.md#5-并发与写互斥)。

> **D140-1 修订（2026-11）**：
> - **写任务默认并行**：内置引擎的写任务一律取**共享写租约**（`shared`），同一根可多个任务并存。租约因此有两态：**共享**（内置写任务）与**独占**（外部智能体整 run、宿主操作 revert / 应用、非任务 `acquire_workdir_write`）——共享 × 共享 = 并存，共享 × 独占与独占 × 独占 = 冲突。
> - **互斥下沉到文件级自动认领**：任务经网关文件工具（write / edit / mkdir / 生成产物）**首次成功写入**某路径时自动认领；同一根下**所有**任务（跨对话、跨 Bot）再写同一路径得到 `WRITE_CLAIMED`，用 `send_to_task` / `wait_for_task` 协调。主动 `claim` 仍可整块占用自己写域内的区域；认领随任务结束释放，纯内存、不是事实来源。单个任务自动认领上限 `TASK_AUTO_CLAIM_MAX`（5000，只防清单无界增长）。**bash 里的 `sed -i` / `npm install`、浏览器下载、外部智能体写入不认领**：只能靠 per-run 影子快照的改动交集在结算时标 `interleaved`（已知限制，任务详情如实展示）。
> - **不再按写域排队**：任务层没有「等写域」互斥了，排队只剩并发额度（独占租约持有者——外部智能体 run、宿主 revert / 应用——占用根时，内置写任务才等独占租约）。`writes: ['…']` 的写域保留为执行期硬边界（域外写入 `WRITE_OUT_OF_DOMAIN`）与展示用途，不再决定谁先跑。
> - **强制收回语义变窄**：收回一个共享持有者只停**该任务**的写入（之后它的文件工具 / 命令可写挂载 / 子代理写入都以 `RUN_READ_ONLY`「写入租约已被用户收回」失败），同一目录的其他写任务继续。只有本对话没有可停的内置共享写任务、而等待者被独占持有者挡住时，才直接收回该独占持有者。界面文案是「停止该任务的写入」，不是「收回整目录」。
> - **per-run 影子快照**：每个写任务在取得租约后开自己的窗口（先快照、结算后再释放租约），结算写 `run_changes`；并行窗口的交集文件标 `interleaved`。详见下文「检查点与回退」。

多个 loop（同一项目组的多个成员 Bot，或选用同一目录的多个对话）可能同时要修改同一个工作目录。

- 同一工作目录可以同时有**多个共享写任务**（D140-1）；**独占**租约（外部智能体 run、宿主 revert / 应用）仍与其他一切串行。未持有租约的 loop 仍可读。
- 写入类工具（write、edit）在任务已持有执行根租约时不再申请新租约（钉住的租约不能换目标，见上）；不在任务里的执行仍自动申请租约。
- 未持有租约的 loop，沙箱中的工作目录为只读；需要执行会改动文件的命令（例如安装依赖、格式化）时，先调用 `acquire_workdir_write()` 申请租约。
- 被**独占**租约挡住时排队等待，对话中显示“等待 X 完成对工作目录的修改”；共享写任务彼此不等，只受并发额度约束。
- 租约在 loop 结束、中断或取消时释放；用户可以在界面中强制收回（D140-1 起含义是「停止该任务的写入」，见上）。
- 租约按目录生效，跨对话共用（认领同样跨对话生效）。
- 每个 loop 最多持有一个租约，不存在死锁。

## worktree 隔离（D140-4）

写任务可以显式选择 `start_task({ isolation: 'worktree' })`，在独立 `git worktree` 中执行（opt-in，不是默认方案）。

- **位置与命名**：`<workdir 父目录>/.worktree/<basename>-<短id>/`（basename 取工作目录名、清洗后截 48 字符；短 id = run id 末 8 位字母数字；重名追加随机后缀；完整路径上限 200）。首次创建 `.worktree/` 时置 0700、写入内容为 `*` 的 `.gitignore`（已存在则不改动、不覆盖）。
- **起点**：`git stash create` 得到的 oid（含用户**未提交的已跟踪改动**），无改动时用 HEAD；`--detach` 创建。仓库没有首次提交、bare 仓库、非 git 目录都创建失败（`WORKTREE_CREATE_FAILED`）。
- **`.worktreeinclude`**（workdir 根下，gitignore 语法）：创建时把列出的**被忽略、存在且非符号链接**的文件复制进树（`git ls-files --others --ignored`），已存在的目标不覆盖。`node_modules` 等不自动复制——任务可能需要在树里自行安装依赖；这是如实告知的已知代价，本期不做 setup 脚本。
- **执行**：树成为任务的 `task_cwd` 与命令 cwd（`policyInfo.cwd`）；任务的写入租约是**树根上的独占租约**（一树一任务），与主目录的共享租约互不冲突；主工作目录对该任务只读（文件工具写主目录被拒），保护规则随树根重锚。双根沙箱规则见 [10 §worktree 双根](10-sandbox.md#worktree-双根d140-4-修订)。
- **结算**：无改动 → 静默保留树（`applyState='kept'`），不出卡；有改动 → 出**一张** `worktree_apply` 卡（改动文件前 20 项、文件总数与增删行）。批准 → 宿主以三方合并应用回主工作目录并删除树（`applied`）；冲突 → 工作目录逐字节还原、树保留（`conflict`，冲突文件列出，可在终端手动合并）；拒绝 → 保留（`kept`）。`worktree_apply` 永不无人值守自动批准。
- **应用的前置条件**：对话仍绑定同一工作目录、且该目录此刻没有任务在写；否则卡记为失败并提示稍后重试，树与改动保留。三方合并在**私有索引副本**上进行（「ours」= 磁盘真实内容），用户真实的 index 不被改写；补丁用 `--no-renames`（rename 退化为 delete + add），保证补丁 / 还原点 / 合并的路径集一致。
- **没有 `run_changes`（DEV-153 ①）**：影子快照窗口要求 `task_cwd` 在主 workdir 内，隔离树是同级的另一目录，`beginTaskWindow` 直接跳过。改动记录以「应用到工作目录」卡的 `files` / 增删行与 `task.applyState` 为准，任务详情页的改动列表对它为空。
- **忽略文件不回流（DEV-153 ②）**：补丁经 `git add -A -N` + `git diff <base>` 生成并尊重 `.gitignore`，只有 tracked 文件与未忽略的未跟踪文件回到工作目录；树里的构建产物 / `node_modules` 等随树删除或回收一并丢弃。
- **`applyState` 是进程内推导（DEV-153 ③④）**：重启后 surviving 树推为 `kept`（冲突也退化为 kept），缺失树推为 `applied`（被 reaper 回收的树会误显示 applied）；结算卡是事实来源。重启时未决定的卡按全局规则取消、树保留，可在终端手动合并；不做「重启后重新出卡」。
- **重试（DEV-153 ⑤）**：任务失败自动重试（同一 run 重新入队）复用原树（保留半成品）；用户 `runs.retry`（新 run）建新树（旧树保留、由 reaper 回收），并把 `task_cwd` 先重算为主工作目录。建树（`stash create`）**不取主 workdir 的租约**（共享租约不排除写任务，独占会违背并行契约），因此同一时刻有主目录写任务时，起点快照可能含它写到一半的内容（DEV-153 ⑥）。
- **远程操作**：worktree 是 detached HEAD，`git_remote`（push / pull / fetch / clone / remote_add / init）在隔离任务里一律 `INVALID_INPUT`，提示先应用到工作目录再推送。
- **孤儿回收**：reaper（启动时一次 + 每日）扫各 workdir 的 `.worktree/`，删除「无对应非终态任务、mtime 超过 7 天、且不是任何已注册挂载」的目录（`git worktree remove --force` + `prune`；失败再按元数据删除），写 `worktree_reaped` 审计。删除对话 / Bot 不删树（改动是用户的资产）。
- **只支持内置引擎 + srt**：ACP 引擎在派发时 `INVALID_INPUT`；默认沙箱后端为 WSL / Podman / Lima 时任务 `WORKTREE_NOT_AVAILABLE`。派发后把 Bot 切成外部智能体也不能绕过（启动前复查当前引擎）。
- **非目标**：worktree 内 `git_remote`、ACP 在 worktree 中运行、自动安装依赖的 setup 脚本。

## 过期检测

- 文件工具在读取时记录文件哈希，写入前比对。
- 文件在读取后被改动过（例如用户在自己的编辑器里改了），写入失败，要求 Bot 重新读取。

## 检查点与回退

Bot 修改的是用户的真实文件，必须可以撤销。

- 每个工作目录在应用数据目录中有一个**影子 git 仓库**，不触碰该目录自身的 `.git`。
- **per-run 窗口（D140-1 修订）**：写任务在取得写入租约后开自己的影子窗口（`beginTaskWindow`，先快照），结算时**先做 after 快照、再释放租约**（`endTaskWindow`）；两次快照之差 + 网关注册的写入归属就是这次执行的 `run_changes`（包括命令行造成的改动）。多个写任务并行时，同一 workdir 的窗口按 run 串行收口：交集文件标 `interleaved`，先结束的并行任务的文件不会被后来的任务冒领。同一 run 重试（同一 run id）时新窗口的文件合并进原行（保留首次尝试的起点）。
- **同一 run 多次持有租约**（非钉住的执行被收回后再写）时，每个文件记自己的首改前 / 末改后快照，整次回退撤销全部窗口；别人夹在窗口之间改过的文件按冲突处理。
- 快照遵循该目录的 `.gitignore`，跳过 `node_modules` 等目录。
- workspace 没有影子仓库：workspace 写任务被取消时只列出它的文件工具写过的文件，不提供整次回退。
- worktree 任务**没有** `run_changes`（窗口要求 `task_cwd` 在主 workdir 内），改动以「应用到工作目录」卡为准，见上文「worktree 隔离」与 DEV-153。
- 执行结束后，Bot 的消息附带**改动摘要卡片**：修改的文件列表、查看 diff、整次回退。
- 回退前检查冲突：如果涉及的文件在之后又被修改，提示用户确认。
- 检查点只保留最近一段时间（保留策略待定参数）。

## 删除

- 删除对话、删除 Bot 都不影响工作目录中的文件。
- 用户从最近列表中移除某个工作目录时，删除其 Workdir 记录与检查点。

## Windows

- 工作目录**实时挂载**进 WSL2 私有发行版，只挂载工作目录本身，不自动挂载整个 C 盘。
- 已知代价：大目录中 git、npm 等操作可能明显变慢。
