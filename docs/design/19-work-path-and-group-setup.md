# 19 对话工作路径与群创建（Work Path & Group Setup）

> 本文原是「工作路径 + 对话内群创建（D60）」的设计。D92 起 D60 的对话内四问创建流程（含 `conversations.setup_state`、`groups.setup.*`、`GroupSetupCard`）已**整体删除**——项目组改为双轮点选创建（先负责人后成员，见 [12-ui-layout.md](12-ui-layout.md#新建项目组) 与 [41-project-team.md](41-project-team.md)），项目目标（原 `description`，现 `goal`）与工作目录在项目详情页补填。文件名保留以避免断链；本文现在只讲**工作路径绑定模型**与 **Bot 访谈里的目录问题**。

## 概念：一个对话对应一个工作路径

工作路径（workdir，界面叫「工作目录」）的**绑定单位是对话**，不是 Bot：

- 单聊：一个 Bot 的单聊只有一个对话，按对话绑路径天然与 Bot 一一对应。
- 项目组：建项目组是为了一个共同的目标，一个项目组对应一个工作路径；组内**所有成员 Bot** 都能读到沟通消息列表、都以该目录为默认工作目录，授权随成员关系自动成立，无需逐个授权。

这一模型自 P04 起就是现状（`conversations.workdir_id`，0038 前为 `project_id`）。项目组创建时不收集工作目录（保持点选即建），建好后在项目详情页「概览」绑定；新成员加入已绑目录的项目组时，沟通里落系统消息告知获得读写权限（见 [08-workdir.md](08-workdir.md)）。

并发安全（多个 Bot 共用同一目录）沿用 [08-workdir.md](08-workdir.md#并发写入租约) 的写入租约：同一目录同一时刻只有一个 loop 可写，读不受限；租约按目录生效、跨对话共用。**本篇不新增并发逻辑。**

## 创建期引导（D59）：Bot 访谈中的目录问题

对话式新建的初始化访谈（见 `bots.setup_state = 'interviewing'`）中，问题分两类：

| 问题 | 发出者 | 时机 |
|---|---|---|
| 首问「您希望我协助您处理哪些事务？」 | core 确定性下发（不经 LLM） | `bots.interview.start` |
| **工作目录**「选择一个本地目录，作为我们共同的工作目录」 | core 确定性下发（不经 LLM） | 首问作答后**立即**插入，先于 LLM |
| 其余问题（名字、职责、语气……） | 访谈中的 Bot（`ask_question` 工具） | 目录问题作答之后的响应 run |

时序：

```text
问候气泡 → 首问卡片 → 用户作答（不触发 LLM）
        → 目录卡片（选择目录… / 暂不设置）
        → 用户选择：绑定 workdir（系统消息）→ 首答连同目录决定一起投递 → 响应 run 开始
```

- **闸门规则**：访谈中的单聊，在目录卡片未作答前，一切用户消息（卡片作答、输入框自由输入、编辑重触发）只落库、不投递 mailbox——目录问题是访谈的必经闸门，保证「先定目录，再开始对话」。
- 目录卡片有两个出口：**选择目录**（原生目录选择器 → `workdirs.select` 绑定，产生与手动绑定一致的「工作目录已绑定为…」系统消息）与**暂不设置**（纯聊天 Bot 不强绑目录；之后随时可用右栏的 workdir 选择器手动绑定）。
- 作答本身落一条 `setupAnswer` 标记的用户消息（不渲染气泡，卡片显示已答态），选择/跳过的决定随消息进入 Bot 上下文；`<workdir>` 提示段在 run 开始时构建，此时绑定已生效。
- 访谈指引提示词同步声明：工作目录由界面询问，run 开始时已是既成事实，不要再问。

## 与既有规则的关系

- 「有 Bot 正在执行时不能切换 workdir」不变：目录绑定发生在任何 run 之前，天然无冲突。
- 「选择与切换在对话中产生系统消息」不变：创建期绑定复用同一条通路，用户与 Bot 看到的授权说明一致。
- 项目组建好后的改名 / 目标 / 成员 / 负责人 / 换绑目录都在项目详情页（[41 §11.3](41-project-team.md#113-项目详情页右栏内容迁移)），不在本篇范围内。
