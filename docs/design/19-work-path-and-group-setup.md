# 19 对话工作路径与群创建（Work Path & Group Setup）

## 概念：一个对话对应一个工作路径

工作路径（project）的**绑定单位是对话**，不是 Bot：

- 单聊：一个 Bot 的单聊只有一个对话，按对话绑路径天然与 Bot 一一对应。
- 群聊：拉群本身就是为了一个共同的事务场景，一个群对应一个工作路径；群内**所有成员 Bot** 都能读到群消息列表、都以该目录为默认工作目录，无需逐个授权。

这一模型自 P04 起就是现状（`conversations.project_id`），本篇不做模型改动，做两件事：

1. 把它**在创建时刻引导落地**：新建 Bot 与新建群时，把「选择工作目录」作为创建流程的固定一步。
2. 把群创建**从弹框搬进对话**，并在创建流程中补齐此前缺失的群语义（本群主要处理什么事务）。

并发安全（多个 Bot 共用同一目录）沿用 [08-project.md](08-project.md#并发写入租约) 的写入租约：同一目录同一时刻只有一个 loop 可写，读不受限；租约按目录生效、跨对话共用。**本篇不新增并发逻辑。**

## 创建期引导（D59）

### Bot：访谈中的目录问题

对话式新建的初始化访谈（见 `bots.setup_state = 'interviewing'`）中，问题分两类：

| 问题 | 发出者 | 时机 |
|---|---|---|
| 首问「您希望我协助您处理哪些事务？」 | core 确定性下发（不经 LLM） | `bots.interview.start` |
| **工作目录**「选择一个本地目录，作为我们共同的工作目录」 | core 确定性下发（不经 LLM） | 首问作答后**立即**插入，先于 LLM |
| 其余问题（名字、职责、语气……） | 访谈中的 Bot（`ask_question` 工具） | 目录问题作答之后的响应 run |

时序：

```text
问候气泡 → 首问卡片 → 用户作答（不触发 LLM）
        → 目录卡片（选择目录… / 暂不设置）
        → 用户选择：绑定 project（系统消息）→ 首答连同目录决定一起投递 → 响应 run 开始
```

- **闸门规则**：访谈中的单聊，在目录卡片未作答前，一切用户消息（卡片作答、输入框自由输入、编辑重触发）只落库、不投递 mailbox——目录问题是访谈的必经闸门，保证「先定目录，再开始对话」。
- 目录卡片有两个出口：**选择目录**（原生目录选择器 → `projects.select` 绑定，产生与手动绑定一致的「项目已绑定为…」系统消息）与**暂不设置**（纯聊天 Bot 不强绑目录；之后随时可用右栏的 project 选择器手动绑定）。
- 作答本身落一条 `setupAnswer` 标记的用户消息（不渲染气泡，卡片显示已答态），选择/跳过的决定随消息进入 Bot 上下文；`<project>` 提示段在 run 开始时构建，此时绑定已生效。
- 访谈指引提示词同步声明：工作目录由界面询问，run 开始时已是既成事实，不要再问。

### 群：对话内创建（D60）

新建群不再弹框：点击「新建群聊」即创建一个**创建中**的群对话（`conversations.setup_state = 'creating'`），四问以确定性卡片在对话中逐题出现，全部由 core 下发、不经任何 LLM：

| 步 | 问题 | 形态 | 落点 |
|---|---|---|---|
| 1 | 群叫什么名字 | 文本输入 | `conversations.title`（完成时生效） |
| 2 | 这个群主要处理什么事务 | 文本输入 | **`conversations.description`（新列）** |
| 3 | 请哪些 Bot 进群 | 成员多选（≥2） | `conversation_members` 行（作答即写入，防中断丢失） |
| 4 | 群工作目录 | 原生目录选择器 / 暂不设置 | `projects.select` 绑定（同单聊语义） |

- 每题作答落一条 `setupAnswer` 标记消息（不渲染气泡），卡片收起为已答态；下一题卡片随即出现。**全程零模型调用**：成员在第 3 步才进群且群创建不触发任何 dispatch，Bot 不会被唤醒。
- `description` 注入群聊的 `<conversation_info>`（「本群主要处理：…」），成员名片之外给 Bot 群定位语义——「归不归我」判断与任务执行的共同依据；同时落一条「群聊创建完成」系统消息，后加入的 Bot 可从群历史读到。
- 完成第 4 步即创建完成：写 `title`、`description`，清 `setup_state`。用户随后发出的第一条消息才触发正常的群聊轮次。
- **放弃创建**：每张未答卡片上有「取消创建」→ 物理删除该对话（沿用对话删除级联，此时仅消息与成员行，无历史负担）；创建中的群在侧栏显示占位名「新建群聊…」，可随时回来继续作答。
- 创建中的群禁止发消息（输入坞禁用）；旧弹框（`NewGroupDialog`）移除，「群设置」弹框保留用于改名与成员管理。

## 实体增量

```text
Conversation
  description        -- 群定位（本群主要处理什么）；单聊为空（新列）
  setup_state        -- 'creating' = 群创建问答进行中；null = 正常（新列）
```

`bots.setup_state`（'interviewing'）语义不变；目录问题不引入新的 Bot 状态——闸门完全由消息流（首问卡片与目录卡片的 seq 关系）推导，重启后自然恢复。

## 与既有规则的关系

- 「有 Bot 正在执行时不能切换 project」不变：目录绑定发生在任何 run 之前，天然无冲突。
- 「选择与切换在对话中产生系统消息」不变：创建期绑定复用同一条通路，用户与 Bot 看到的授权说明一致。
- 群创建完成后，改名 / 加减成员 / 换绑目录都走既有入口，不在本篇范围内。
