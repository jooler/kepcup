# 12 界面

参考 Grok Bot 的三栏布局，用 shadcn-svelte 组件组合实现（Sidebar + Resizable）。

## 视觉风格

参考 Grok Bot：简单、扁平。

- 中性色为主，只用一个强调色；支持浅色与深色模式，默认跟随系统。
- 扁平：不用渐变与重阴影，层次靠留白、浅色分隔线和背景明度区分。
- 字体：系统字体；代码与路径使用等宽字体。
- 动效克制：过渡 150～200ms，只用于状态变化，不做装饰性动画。
- 基于 shadcn-svelte 默认的中性主题调整，不另起一套设计系统。

## 布局

### 左栏

- 对话列表：单聊与群聊。
- 底部是用户头像；点击后弹出二级菜单，跳转到设置、通讯录等页面。

### 中栏：对话

从上到下：

1. 消息列表（虚拟滚动）
2. 待发送队列（有内容时显示，可修改、删除、调整顺序）
3. 消息输入框
4. project 选择器

消息列表中除普通消息外，还有以下卡片：

| 卡片 | 用途 |
|---|---|
| 环境申请确认 | Bot 申请安装宿主层环境，用户同意或拒绝 |
| git 远程操作确认 | Bot 申请执行 push / pull / fetch 等 |
| 改动摘要 | 一次执行修改的文件列表、查看 diff、整次回退 |
| 访问授权 | Bot 申请访问 project 以外的路径：仅这一次 / 本对话内一直允许 / 拒绝 |
| 沙箱外执行确认 | Bot 申请在沙箱外执行某条命令，显示完整命令并醒目标出风险 |
| 命令确认 | 逐条确认模式下，每条命令执行前确认 |
| 凭据注入 | Bot 申请凭据（如 sudo 密码）：掩码输入、可选「记住到本对话结束」，折叠记录不含值 |
| 系统消息 | 例如“所有 Bot 都未响应，请指定一个 Bot”（附可点击的 Bot 列表）、project 切换 |
| 任务卡（D75） | 对话轮派出的任务：状态、排队原因、进度、注入行、取消；取消后附改动摘要 |
| 任务问题卡（D75） | 任务向用户提问（`ask_user`），点选即答 |
| 设置引导卡（输入坞上方） | 功能缺配置时就地呈现对应设置组件（模型 / 图像生成等，与设置页同一份数据），完成后对话自动继续（18-inline-setup） |

### 右栏：Bot 相关

- **单聊**：当前 Bot 的详情，用标签页切换：
  - 配置（Profile）
  - 记忆
  - Skills
  - Wiki
- **群聊**：先显示群信息与成员列表，点击某个 Bot 进入它的详情。
- 右栏同时显示当前对话中各 Bot 的有效访问授权，可以撤销；处于逐条确认模式时持续提示。

## 交互反馈

> **D75 修订**：
> - **状态行**（D55）= 对话轮自己的一行 + 进行中任务合并的一行：一个任务显示标题与当前活动，多个任务显示条数与最近活动、可展开。排队中的写任务在租约层等待时保留「强制收回」按钮；在任务层排队（同一 workdir 已有写任务）时不给（待确认，见 DEV-015）。被强制收回租约的写任务继续运行但失去写权限（之后的写入返回「写入租约已被用户收回」，待确认，见 DEV-018）。任务的中间说明在消息流中标为该任务的进度。
> - **任务卡**（`cardType='task'`，随 `task.updated` 重绘）：标题、状态、排队原因、等待用户输入、最近进度、注入行（引擎没收下的标「未送达」）、取消按钮；取消后附改动摘要——project 写任务给计数与整次回退，workspace 写任务只列文件工具写过的文件并说明没有回退；失败任务可重试，缺设置的交给对话内设置卡。
> - **任务问题卡**：任务调用 `ask_user` 时出现，绑定该任务；点选选项直接注入任务（不经对话轮），卡片显示所选答案。
> - 对话轮永不等用户（待确认，见 DEV-014）：下文「焦点三」的待确认卡片只会暂停**任务**。
> - 未实现：Bot 详情栏 / 对话头部的进行中任务数；执行记录页任务与对话轮分列。
>
> 见 [30 §6.3](30-supervisor-and-tasks.md#63-界面)。

原则：**用户目光焦点所在的位置，反馈要即时、细致、明确**；焦点以外的事件用轻量方式提示，不打断用户。

### 焦点一：输入区（最重要）

- 按下发送后，内容立即出现在待发送队列中（带轻微的进入过渡），输入框同步清空。
- 队列有内容且输入框为空时，输入框内显示提示文字，例如“再按 Enter 发送 3 条消息”；`Cmd/Ctrl+Enter` 的作用同样在提示中说明。
- 队列中每一项可以直接点击修改、拖动排序、删除；正在编辑的项有明确的高亮。
- 输入 `@` 时弹出群成员候选，支持键盘选择；已选中的 Bot 在输入内容中以标签形式显示。
- 拖入文件时，输入区整体高亮为可放置状态。
- project 选择器显示当前目录名；悬停显示完整路径；目录不可用时显示警示状态。
- 发送后，消息列表末尾立即出现目标 Bot 的“正在处理”状态，让用户确认消息已被接收。

### 焦点二：消息流末尾

- **Bot 状态**：状态行排在消息流末尾——它的位置就是下一条消息会出现的位置（不是悬浮在输入组件上方的固定条）。样式只保留绿点装饰与状态文字，无边框、无背景；**这里不允许取消**，不提供取消按钮，也不提供执行步骤展开（唯一例外：等待项目租约时附「强制收回」按钮）。状态文字按活动切换：排队中… / 请稍等…（尚无任何输出）/ 正在调用工具 X…（工具名随调用更新，如“正在检索对话…”“正在执行命令…”）/ 工具自报文本；**本 Bot 的新消息落库时状态行让位消失**，下一个工具活动再出现，如此交替直到最终回答出现、状态行随之移除。
- **命令交互输入**：交互模式命令（见 [15-interactive-execution.md](15-interactive-execution.md)）在步骤面板中显示实时输出尾部与单行输入框，用户输入直达进程 stdin；疑似需要输入时徽标提醒。
- **群聊**：显示响应顺序，例如“A 正在回复，B 排队中”；判断阶段显示“正在确认由谁回复”。响应中的 Bot 状态行同样排在消息流末尾（同样只有绿点与文字）。
- **新消息**：用户停留在底部时自动滚动；不在底部时不打断阅读，显示“有新消息”悬浮提示，点击回到底部。
- **失败与超时**：在对应位置内联显示原因，并提供重试。

### 焦点三：待确认卡片

- Bot 等待确认时 loop 处于暂停状态。卡片出现在消息流末尾、紧贴输入区上方，并有明显的强调样式。
- 支持键盘操作：例如 Enter 批准、Esc 拒绝（具体按键实现时确定）。
- 处理后卡片立即折叠成一行记录（例如“已允许 A 读取 ~/Desktop/a.txt（仅这一次）”），执行随即恢复。
- 同时有多张待确认卡片时，逐张聚焦处理。

### 焦点以外

- 左栏对话列表：未读数、有 Bot 正在执行的标记、**有待确认操作的醒目标记**。
- 窗口不在前台时有待确认操作：发送系统通知。
- 非关键的后台事件（例如 Wiki 入库完成）使用 toast，自动消失。
- 无人值守模式开启期间：窗口顶部显示持续的醒目横幅，托盘图标同步显示状态。

### 通用

- 所有可交互元素有清晰的键盘焦点样式，支持完整的键盘操作。
- 加载中使用骨架屏，不使用整页转圈。
