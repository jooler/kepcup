# 12 界面

参考 Grok Bot 的三栏布局，用 shadcn-svelte 组件组合实现（Sidebar + Resizable）。项目组会话不用右栏，内容区承载模块视图与项目详情页（见下文「项目组外壳」）。

## 视觉风格

参考 Grok Bot：简单、扁平。

- 中性色为主，只用一个强调色；支持浅色与深色模式，默认跟随系统。
- 扁平：不用渐变与重阴影，层次靠留白、浅色分隔线和背景明度区分。
- 字体：系统字体；代码与路径使用等宽字体。
- 动效克制：过渡 150～200ms，只用于状态变化，不做装饰性动画。
- 基于 shadcn-svelte 默认的中性主题调整，不另起一套设计系统。

## 布局

### 左栏

- 对话列表：单聊与项目组，可按用户自建的分组归类（见下文「对话分组」）。单聊行显示 Bot 头像，项目组行显示成员头像堆叠（见下文「项目头像堆叠」）。
- 顶部「+」：搜索 Bot 开始对话、新建 Bot、新建项目组（见下文「新建项目组」）。
- 底部是用户头像；点击后弹出二级菜单，跳转到设置、通讯录等页面。

#### 对话分组

实现：`features/sidebar/sidebar-sections.ts`（纯逻辑，单测 `sidebar-sections.test.ts`）+ `sidebar-sections.svelte.ts`（rune store，每次变更即落盘），渲染在 `AppSidebar.svelte`。

- **缺省**：所有对话都在「未指定」；只有这一组时不画组名，列表与没有分组时一样。建了自定义分组后，「未指定」也作为一组带组名显示。组内对话保持会话列表原有的时间顺序。
- **归属**：右键对话 →「移动到」子菜单，列出全部分组（当前所在组打勾）和「新建分组」。新建分组就地输入名称（最长 40 字），创建后排在最前并把这条对话移进去。移入一个折叠中的分组会自动展开它。对话本身不能拖拽，跨组只经「移动到」。
- **管家**（D70）不进任何分组：有组名时单独固定在所有分组之上，无组名时排在列表最前；它的右键菜单没有「移动到」；之前若被移入过分组，归属会被自动清掉。
- **组名**：点击折叠 / 展开，折叠时显示组内对话数。按住组名上下拖动可重排分组（显示插入线，落回原位不算改动，拖到列表上下边缘自动滚动）。「未指定」同样可折叠、可拖动。
- **重命名 / 删除**：右键自定义组名 →「重命名分组」（行内输入，回车或失焦保存，Esc 取消）/「删除分组」（不二次确认，toast 提示）。删除只删分组，组内对话回到「未指定」；删掉最后一个自定义分组后组名不再显示。「未指定」不能重命名或删除。
- **图标模式**（侧栏收窄成头像列）只沿用分组顺序、忽略折叠：没有组名可点，折叠会让对话找不回来。
- **存储**：分组是渲染层的本机 UI 偏好（与侧栏宽度同层），存在 renderer 的 localStorage 键 `kepcup.sidebar.sections.v1`（分组目录、顺序、对话归属、折叠状态），**不进 core 数据库**。因此它不随应用数据同步或备份，清空 localStorage 即丢失（对话全部回到「未指定」）；localStorage 按 origin 隔离，开发模式（dev server 地址）与打包版（`file://`）各存一份、互不相通。读入时丢弃坏数据和指向不存在分组的归属；会话列表加载完成后，已删除的会话（含删除 Bot 后不再列出的单聊）的归属也会清掉。写入失败（配额满等）静默忽略，下次启动回到缺省。

#### 项目头像堆叠

项目组的侧栏头像用成员头像**马赛克**堆叠（`avatars/ProjectAvatarStack.svelte`，布局 `avatars/project-avatar-layout.ts`），用在左栏对话行与工作台的成员头像（`MemberAvatar`）。

- 布局：1 个居中占满；2 个并排；3 个品字（上一下二）；4 个田字；5 个及以上按成员 id 拼成的种子伪随机摆放与叠放，直径相差不超过 20%。种子相同布局就相同，不会每次渲染跳动。所有瓦片都收在容器范围内（容器不裁切）。
- 始终把当前用户（`avatars/UserAvatar.svelte`，占位字母，尚无个人头像）排在第一个，其后才是 Bot，总数含用户封顶 9 个；`includeUser={false}` 可关掉。成员未知（没有任何 Bot）时显示占位图标，不会只画一个用户头像。
- 重叠处不再描边，改为字影：每个头像的字形 / 字母带 1px 阴影，朝向马赛克中心，颜色与主题相反（`app.css` 的 `.project-avatar-*-shadow`），所以瓦片本身不裁圆，预置头像按形状显示。
- 左栏用会话列表附带的 `memberPreviews`（按入组顺序取前 9 个，`PROJECT_MEMBER_PREVIEW_MAX`）。
- 项目顶栏的重叠堆叠是另一套：`ProjectMembersMenu` 自建（后一个压前一个、负责人在最前带冠标、最多画 5 个 + `+N`），与侧栏马赛克语义不同，不复用。

#### 新建项目组

「+」→「新建项目组」，没有弹框：主区域切换为创建视图（`ChatView` 的 `project-compose-view`），顶部一条「To:」输入条（`ProjectComposeBar.svelte`，纯逻辑 `project-compose.ts`），下方是候选 Bot 列表。**双轮选择**：

- **第一轮 · 负责人（单选）**：点候选或输入名字回车；输入新名字回车 = 新建一个空画像的 Bot 并直接作为负责人（负责人行为由项目上下文注入，不依赖 Profile）。候选排除管家。选定后进入第二轮（负责人芯片固定最前、带冠标，点 ✕ 退回第一轮，已选成员保留）；输入为空时回车提示「请先选择项目负责人」。
- **第二轮 · 成员（多选）**：点候选或 `Ctrl/⌘+1`～`9` 选前 9 个（候选右侧标出快捷键），输入文字过滤；已选成员以带头像的标签显示，点 ✕ 移除，输入框为空时退格删掉最后一个、无成员时退格退回第一轮；候选不含负责人与管家。**空回车创建**：已选 ≥1 位成员即调 `projects.create`（`memberBotIds = [负责人, …成员]`），默认名称按「负责人, 成员…」拼接（受名称长度上限截断），随即进入该项目组；不足 1 位成员只提示、不建。
- **取消**：Esc 或输入条右侧 ✕，回到创建前的会话（创建视图期间不清当前会话）；打开任何会话也会结束创建视图。
- 项目组在创建那一刻才产生：创建视图本身不是会话，不进左栏。创建时不收集项目目标与工作目录，之后在项目详情页补充。

### 项目组外壳

项目组会话的内容区顶栏改为**实心块**（不再是单聊的浮动渐隐药丸），高度两行；组件在 `features/project/`（`ProjectView` / `ProjectHeader` / `ProjectTabs` / `ProjectMembersMenu` / `ModulePlaceholder`）。

- **左两行**：第一行项目名；第二行模块 tab，读 shared 的 `PROJECT_MODULES` 注册表（`chat / wiki / board / okr / calendar`），`planned` 模块灰显、悬停提示「即将推出」、不可点。
- **沟通 tab 徽标** = 未读数 + 待确认标记（`project-chat-badge.ts`）：用户停在 Wiki 等其他 tab 时不会漏掉审批卡。
- **右侧成员堆叠与弹层**：重叠头像堆叠（负责人排第一带冠标，超过 5 个显示 `+N`）；点开成员下拉（`ProjectMembersMenu`）：成员列表（负责人置顶带标）+ 搜索添加成员 +「管理成员…」（跳详情页成员分区）。
- **设置按钮 ⚙**：打开**项目详情页**——内容区里的页面（`ProjectSettingsPage`，非弹框），tab 行不新增项、⚙ 呈选中态；再点任一 tab 返回。状态 `shell.projectView`（内存，不持久化），`chat.select()` 时重置回沟通。详情页五分区：概览（名称、项目目标、工作目录、负责人）/ 成员 / 授权 / 定时与监看 / 危险区（删除项目组）。
- **窄屏**：第一行「返回 + 项目名 + ⚙」，第二行 tab 横向滚动；头像堆叠紧凑保留。
- **右栏**：项目组会话不渲染 `RightPanel`，右栏只服务单聊；`shell.rightPanelCollapsed` 等右栏状态对项目组无意义。

### 中栏：对话

从上到下：

1. 消息列表（虚拟滚动）
2. 消息输入框
3. workdir 选择器

消息列表中除普通消息外，还有以下卡片：

| 卡片 | 用途 |
|---|---|
| 环境申请确认 | Bot 申请安装宿主层环境，用户同意或拒绝 |
| git 远程操作确认 | Bot 申请执行 push / pull / fetch 等 |
| 改动摘要 | 一次执行修改的文件列表、查看 diff、整次回退 |
| 访问授权 | Bot 申请访问 workdir 以外的路径：仅这一次 / 本对话内一直允许 / 拒绝 |
| 沙箱外执行确认 | Bot 申请在沙箱外执行某条命令，显示完整命令并醒目标出风险 |
| 命令确认 | 逐条确认模式下，每条命令执行前确认 |
| 凭据注入 | Bot 申请凭据（如 sudo 密码）：掩码输入、可选「记住到本对话结束」，折叠记录不含值 |
| 系统消息 | 例如「负责人已更换为 X」「X 已加入项目组」、workdir 切换 |
| 协作暂停卡（D92） | Bot 间自动往返触发熔断后出现：「协作已自动往返 N 次，已暂停」，继续（补投 pending）或停止；带回合状态，Bot 已停 / 回合已停时只读展示 |
| 任务卡（D75） | 对话轮派出的任务：状态、排队原因、进度、注入行、取消；点击卡面打开任务执行过程页（Agent 消息列表、工具调用与 metadata，见 [42](42-task-run-view.md)） |
| 任务问题卡（D75） | 任务向用户提问（`ask_user`），点选即答 |
| 设置引导卡（输入坞上方） | 功能缺配置时就地呈现对应设置组件（模型 / 图像生成等，与设置页同一份数据），完成后对话自动继续（18-inline-setup） |

### 右栏：Bot 相关（仅单聊）

- **单聊**：当前 Bot 的详情，用标签页切换：
  - 配置（Profile）
  - 记忆
  - Skills
  - Wiki
- 项目组会话不渲染右栏（项目信息、成员、授权、定时与监看在项目详情页，见上文「项目组外壳」）。
- 右栏同时显示当前对话中各 Bot 的有效访问授权，可以撤销；处于逐条确认模式时持续提示。

## 交互反馈

> **D75 修订**：
> - **状态行**（D55）= 对话轮自己的一行 + 进行中任务合并的一行：一个任务显示标题与当前活动，多个任务显示条数与最近活动、可展开。排队中的写任务在租约层等待时保留「强制收回」按钮；在任务层排队（同一 workdir 已有写任务）时不给（见 DEV-015）。被强制收回租约的写任务继续运行但失去写权限（之后的写入返回「写入租约已被用户收回」，见 DEV-018）。任务的中间说明在消息流中标为该任务的进度。
> - **任务卡**（`cardType='task'`，随 `task.updated` 重绘）：标题、状态、排队原因、等待用户输入、最近进度、注入行（引擎没收下的标「未送达」）、取消按钮；取消后附改动摘要——workdir 写任务给计数与整次回退，workspace 写任务只列文件工具写过的文件并说明没有回退；失败或中断的任务可重试（中断且有外部副作用时为「检查后重试」，见 [30 §7.4](30-supervisor-and-tasks.md#74-崩溃与恢复d49d67)），缺设置的交给对话内设置卡。点击卡面或「查看执行过程」打开任务执行过程页：原对话组件 `display: none`，主区显示该任务的 Agent 消息列表、工具调用与 metadata（见 [42](42-task-run-view.md)）。
> - **任务问题卡**：任务调用 `ask_user` 时出现，绑定该任务；点选选项直接注入任务（不经对话轮），卡片显示所选答案。
> - 对话轮永不等用户（见 DEV-014）：下文「焦点三」的待确认卡片只会暂停**任务**。
> - 未实现：Bot 详情栏 / 对话头部的进行中任务数；执行记录页任务与对话轮分列。
>
> 见 [30 §6.3](30-supervisor-and-tasks.md#63-界面)。

原则：**用户目光焦点所在的位置，反馈要即时、细致、明确**；焦点以外的事件用轻量方式提示，不打断用户。

### 焦点一：输入区（最重要）

- 按下发送（发送按钮或 Enter，`Cmd/Ctrl+Enter` 等效）后消息立即发出，输入框同步清空；发出的内容立刻以用户气泡出现在消息列表中。
- 输入 `@` 时弹出成员候选（项目组为成员，单聊为可委派的 Bot），支持键盘选择；已选中的 Bot 在输入内容中以标签形式显示。
- 拖入文件时，输入区整体高亮为可放置状态。
- workdir 选择器显示当前目录名；悬停显示完整路径；目录不可用时显示警示状态。
- 发送后，消息列表末尾立即出现目标 Bot 的“正在处理”状态，让用户确认消息已被接收。

### 焦点二：消息流末尾

- **Bot 状态**：状态行排在消息流末尾——它的位置就是下一条消息会出现的位置（不是悬浮在输入组件上方的固定条）。样式只保留绿点装饰与状态文字，无边框、无背景；**这里不允许取消**，不提供取消按钮，也不提供执行步骤展开（唯一例外：等待工作目录租约时附「强制收回」按钮）。状态文字按活动切换：排队中… / 请稍等…（尚无任何输出）/ 正在调用工具 X…（工具名随调用更新，如“正在检索对话…”“正在执行命令…”）/ 工具自报文本；**本 Bot 的新消息落库时状态行让位消失**，下一个工具活动再出现，如此交替直到最终回答出现、状态行随之移除。
- **命令交互输入**：交互模式命令（见 [15-interactive-execution.md](15-interactive-execution.md)）在步骤面板中显示实时输出尾部与单行输入框，用户输入直达进程 stdin；疑似需要输入时徽标提醒。
- **项目组**：显示响应顺序，例如“A 正在回复，B 排队中”；路由阶段显示“正在确认由谁回复”。响应中的 Bot 状态行同样排在消息流末尾（同样只有绿点与文字）。
- **新消息**：用户停留在底部时自动滚动；不在底部时不打断阅读，显示“有新消息”悬浮提示，点击回到底部。
- **失败与超时**：在对应位置内联显示原因，并提供重试。

### 焦点三：待确认卡片

- Bot 等待确认时 loop 处于暂停状态。卡片出现在消息流末尾、紧贴输入区上方，并有明显的强调样式。
- 支持键盘操作：例如 Enter 批准、Esc 拒绝（具体按键实现时确定）。
- 中途权限卡（访问、命令、MCP / 智能体工具、git 远程、沙箱外执行、外发）只在输入区上方弹出，处理后消失、执行随即恢复，**不在对话里留记录**（ef2a565）；例外：无人值守自动决定的卡（用户从没见过它）与外发 / 带污点标记的卡，决定后在**当前会话**里留一行折叠记录（例如“读取 ~/Desktop/a.txt · 已自动批准”，含执行回执）——这一记录是随消息事件送达界面的内存态提示，不落库、不进 Bot 上下文，切换对话或重启应用后即消失。技能导入、环境安装、移交等卡片处理后折叠成一行记录留在对话里。
- 同时有多张待确认卡片时，逐张聚焦处理。
- 例外表面：任务执行过程页打开期间对话整体隐藏，待确认卡片改在该页时间线下方呈现（同一份数据与键盘约定，见 [42-task-run-view.md](42-task-run-view.md) 的「审批卡（权限请求）」）。

### 焦点以外

- 左栏对话列表：未读数、有 Bot 正在执行的标记、**有待确认操作的醒目标记**。
- 窗口不在前台时有待确认操作：发送系统通知。
- 非关键的后台事件（例如 Wiki 入库完成）使用 toast，自动消失。
- 无人值守模式开启期间：窗口顶部显示持续的醒目横幅，托盘图标同步显示状态。

### 通用

- 所有可交互元素有清晰的键盘焦点样式，支持完整的键盘操作。
- 加载中使用骨架屏，不使用整页转圈。
