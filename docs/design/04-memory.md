# 04 记忆

记忆分两层：

- **共享层：用户画像**。记录“用户是谁”，所有 Bot 都可读。
- **私有层：各 Bot 自己的记忆**。记录该 Bot 与用户的关系和自身状态。

## 条目结构

两层使用同一种条目结构：

```text
MemoryItem
  id
  owner          user_profile | bot:{id}
  kind           fact | preference | commitment | feedback | episode | lesson | self_note
  content        一句自然语言陈述
  source         explicit（用户明确说的）| inferred（推断的）
  evidence       [message_id, run_id]      -- 来源链路，可追溯、可撤回
  origin         private | group           -- 从哪类对话得来
  confidence     0~1
  sensitivity    normal | sensitive
  valid_until    可选，时效性信息必填
  status         active | superseded | retracted
  supersedes     被替换的旧条目 id
  last_used_at, use_count
```

## 共享层：用户画像

分类：

- **基本信息**：称呼、语言、时区、职业
- **沟通偏好**：详略、格式、语气
- **工作与项目**：技术栈、当前在做的项目
- **兴趣与习惯**
- **边界与禁忌**：不喜欢什么、不要做什么
- **近期状态**：本周在忙什么、最近的目标（必须带过期时间）

画像整理 loop 将画像编译成一张约 400 token 的**画像卡片**，每次注入；完整条目通过工具按需查询。

### 共享规则

- 私聊中得到的用户信息**默认进入共享画像**。
- 以下内容不进入共享层，只留在该 Bot 的私有记忆中：
  - 敏感类信息
  - 用户声明“这件事只告诉你”的内容

## 私有层：各 Bot 的记忆

**关系记忆**

- 承诺与约定（`commitment`）：结构化，带截止时间，与调度器联动。承诺绑定到做出它的对话；该对话被删除，或 Bot 被移出该群时，承诺作废，对应的定时任务一并取消。
- 用户对我的反馈（`feedback`）：例如“他嫌我太啰嗦”。
- 重要的共同经历（`episode`）：只记里程碑，并指向对应的对话或执行记录。

**自我状态**

- 经验教训（`lesson`）：例如“上次用 X 方法失败了，原因是……”。
- 自我笔记（`self_note`）。
- “我手上在做什么”不存为记忆，每次从执行记录和承诺中实时汇总。Bot 在任一对话中都能看到自己在其他对话中进行中事项的**标题**，看不到内容。

### 画像与私有记忆的分流

- 关于用户本人的事实 → 共享画像
- 关于用户与我之间的关系（我的承诺、他对我的评价）→ 私有记忆

## 记什么、不记什么

**记：**

- 用户明确要求记住的事
- 稳定的事实和偏好（同一偏好出现 2 次以上，或用户明确说过）
- 用户对 Bot 行为的纠正和反馈
- 承诺、未完成的事、已做出的决策及原因
- 失败或成功带来的经验教训

**不记：**

- 密码、token、证件号等凭据：永远不记，发现时在对话中提醒用户
- 敏感类别（健康、财务、感情、他人隐私）：除非用户明确要求记住；即使记住也默认不进共享层
- 闲聊和一次性上下文：对话历史里已有，用查询工具即可找到，不重复存
- 对用户性格、情绪的主观推断，尤其是低置信度的
- 世界知识（归 Wiki）、操作流程（归 Skill）、文件内容（归 workspace 或附件）
- 来自网页、文件、其他 Bot 发言的“关于用户的说法”：**用户画像只接受以用户本人消息为证据的条目**，防止记忆被污染

用户控制：

- 用户说“这件事只告诉你”→ 条目标记为不进共享层
- 用户说“忘掉 X”→ 对应条目撤回

## 写入流程

1. **显式写入**：用户说“记住……”，响应 loop 调用 `remember` 工具，进入写入队列后立即生效。
2. **事后反思**：每次响应 loop 结束后，启动低优先级的反思 loop，从本次对话和执行过程中提取候选条目，与已有记忆去重，然后：
   - 写入本 Bot 的私有记忆
   - 用户画像候选作为**提案**交给画像整理 loop
3. **画像整理**：全局唯一的写入者，负责合并、处理冲突、重新编译画像卡片。
   - 冲突优先级：明确说过的 > 推断的；新的 > 旧的
   - 无法判断时保留两条并标注，由 Bot 找合适时机向用户确认
4. **定期整理**（类似“睡眠”，每个 Bot 每天一次）：合并重复、清理过期、淡化长期未使用的条目、把一段时期的经历压缩成摘要。

## 删除时的记忆处理

| 操作 | 私有记忆 | 共享用户画像 |
|---|---|---|
| 删除对话 | 该对话中的承诺作废，其余保留 | 保留 |
| 从群中移除 Bot | 该 Bot 在此群中的承诺作废，其余保留 | 保留 |
| 删除 Bot | 全部删除 | 该 Bot 贡献的条目保留 |

## 注入方式

| 内容 | 何时注入 | 参考预算 |
|---|---|---|
| Profile 人设 | 总是 | ~800 token |
| 用户画像卡片 | 总是 | ~400 token |
| 我的状态（到期的承诺、进行中事项标题） | 总是 | ~300 token |
| 相关记忆 top-k（以触发消息做关键词 + 向量混合检索） | 每次 | ~600 token |
| Wiki 主题目录 | 总是 | ~200 token |
| Skills 列表（仅名字和描述） | 总是 | ~500 token |

预算数值为初始参考，后续按实际效果调整。

注入规则：

- 注入的记忆都带 id，并标明“可能已过时，关键决策前请确认”。
- Bot 发现记忆有误时调用 `memory_feedback(id, outdated)`。
- 群聊中，来自私聊的记忆标注“来自私聊”，Bot 需像真人一样有分寸，不在群里透露私聊内容。

记忆查询工具：

| 工具 | 用途 |
|---|---|
| `recall_memory(query)` | 检索本 Bot 的记忆 |
| `get_user_profile(category)` | 查询用户画像的完整条目 |
| `list_commitments()` | 列出本 Bot 的承诺与待办 |
| `remember(content)` | 显式写入 |
| `memory_feedback(id, reason)` | 反馈某条记忆有误或过时 |

## 用户可见与可控

前端提供“Bot 大脑”面板，用户可以查看、编辑、删除所有记忆条目（包括共享画像）。
