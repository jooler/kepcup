# 13 访问授权（软隔离）

## 原则

- 与各类编程 Agent 一致：**默认范围小，越界时向用户申请授权，批准后继续。**
- 软硬结合：
  - **文件工具**（读、写、编辑、搜索、列目录）由工具网关按路径精确检查，越界即请求授权（软隔离）。
  - **命令行**在沙箱中执行，沙箱规则在每条命令执行前按当前授权实时生成（硬隔离）。命令可能间接访问任意路径，无法靠解析命令判断，因此不能只靠软隔离。

## 默认可访问范围

| 位置 | 默认 |
|---|---|
| 当前 workspace | 读写 |
| 当前对话的 project | 读写（写入需持有写入租约，见 [08-project.md](08-project.md#并发写入租约)） |
| 系统目录、工具链目录 | 只读 |
| 本机其他位置 | 读、写都需授权 |
| `~/.ssh`、系统钥匙串、`~/.aws`、`~/.config/gh` 等敏感位置 | 需授权，授权卡片醒目警告 |
| `~/.kepcup`（应用数据目录） | 永远不可授权 |

## 授权

```text
Grant
  id
  bot_id
  conversation_id
  path            -- 文件或目录
  access          -- read | write（write 包含 read）
  duration        -- once | conversation
  created_at
  revoked_at
```

- 授权**只给提出申请的 Bot，只在当前对话内有效**。群里其他 Bot 需要时各自申请。
- 有效期两种：
  - **仅这一次**：本次执行结束即失效。（**D75 修订**：收紧为**单次工具调用**即失效，并加绝对时限 `GRANT_ABSOLUTE_TTL_MS`（10 分钟）兜底——任务可长达数小时，「随 run 结束才失效」在长任务里等于「整个任务一直允许」；需要整任务有效的改用「本对话内一直允许」。「单次工具调用」= **使用该授权的那一次调用**：越界当场批准的授权归批准它的调用、调用结束即撤销；`request_access` 的预授权在被用到前不属于任何调用，由**随后第一次真正用到它的调用认领并消费**（文件工具命中，或并入某条命令的沙箱策略——`bash` 把可见的 once 授权全部并入并消费）；同一 run 内并行的调用不共享 once 授权；外部智能体权限请求的「仅这一次」不落授权。见 DEV-009 与 [30 §7.3](30-supervisor-and-tasks.md#73-授权与审批d37-收紧)）
  - **本对话内一直允许**：直到用户撤销。
- 没有永久授权。
- 用户可以在界面中查看当前对话的全部授权，随时撤销。
- **撤销即中断（D78）**：用户在任务运行中主动撤销授权时，受影响的进行中任务（`running` / `waiting_approval` / `waiting_lease`）立即中断：中止执行、取消其（含子代理的）待决审批（因此被取消审批的外部副作用台账行结为 `denied`，其余执行中的行改为结果未知）、任务记为 `interrupted`（原因 `permission_revoked`，任务卡显示「授权已被撤销，任务已中断。请检查已完成的操作后再重试」），之后只能由用户在任务卡上检查后重试（[30 §7.4](30-supervisor-and-tasks.md#74-崩溃与恢复d49d67)）；撤销处提示「已中断 N 个进行中的任务」，不弹确认。
  - 触发源：撤销路径授权（`grants.revoke`）→ 中断该授权所属 Bot 在该对话里的任务；「仅这一次」授权只中断它所属 run 的任务（子代理的上溯到父任务；属于对话轮的不中断任何任务）。MCP：server 被删除 / 停用、被移出 Bot 的勾选、`autoApprove` 由开改关（工具列表已知时只算真正由免审变成确认的工具）、逐工具停用或有效审批由免审改为确认 → 中断勾选了该 server 的 Bot 的任务（按 Bot 粒度，不看任务是否用过该工具）。
  - 同一路径（D77，W8）：切换 Bot 的浏览器资料（含共享资料被删除后改回私有）→ 中断该 Bot 用过浏览器的进行中任务，原因 `browser_profile_changed`，任务卡显示「浏览器资料已切换，任务已中断。请检查已完成的操作后再重试」（[14](14-models-and-browser.md#隔离)）。
  - 不算撤销：「仅这一次」授权随调用结束或绝对时限自动失效、任务自然结束、无关设置的保存。还在排队（submitted）的任务不中断，启动时按新权限执行；对话轮不中断（它只读，撤销后其后续调用自然失败）。
- 删除对话、删除 Bot、从群中移除 Bot 时，相关授权一并失效。
- 授权范围内的写入同样需要写入租约（按目录）。
- 可回退性：
  - 文件工具的写入在修改前逐文件备份，可以回退。
  - 命令行对授权目录的改动不保证可以回退，授权卡片中会注明。

## 流程

### 文件工具越界

1. 工具网关发现目标路径超出当前可访问范围，loop 暂停，对话中出现**授权卡片**：申请的 Bot、路径、读还是写、Bot 给出的原因。
2. 用户选择：仅这一次 / 本对话内一直允许 / 拒绝。
3. 批准后继续执行；拒绝时工具向 Bot 返回“用户拒绝”，由 Bot 自行调整做法。

- 即使用户在消息中明确要求处理项目外的文件，也仍然弹出授权卡片（一次点击即可），防止 Bot 误解路径。
- Bot 也可以在批量操作前主动调用 `request_access(path, access, reason)` 一次性申请。
- 等待授权期间 loop 处于暂停状态，不消耗 token；用户的新消息照常在下一步注入。（**D75 修订**：只有**任务**会等审批——对话轮永不等用户，越界读取当场失败（`PATH_OUT_OF_SCOPE`）并提示派任务，不发起审批（见 DEV-014）；任务等审批期间用户的新消息进入下一个对话轮，由 Bot 决定是否 `inject_task`。）

### 命令行

- 每条命令执行前，按 workspace、project（写入租约）与当前有效授权生成沙箱规则。
- 命令因沙箱限制失败时，沙箱会报告被拦截的路径；Bot 据此调用 `request_access` 申请授权，批准后重新执行（选「仅这一次」时，预授权由重跑的那条命令认领；中间若先跑了一条无关命令，预授权会被它用掉，需要重新申请）。
- 命令的交互执行（交互模式、凭据注入）与各平台的降级规则见 [15-interactive-execution.md](15-interactive-execution.md)。

### 沙箱外执行

- Bot 可以调用 `request_unsandboxed(command, reason)`，申请在沙箱外执行某一条命令（例如需要调用 Docker、系统钥匙串的命令）。
- **每次都必须由用户确认**，没有“一直允许”；卡片显示完整命令并醒目标出风险。
- 沙箱外执行的改动不保证可以回退。

### 沙箱不可用时：逐条确认模式

- 当前机器上沙箱不可用时（例如 Windows 尚未启用 WSL2、Linux 尚未解除用户命名空间限制），代码执行**降级为逐条确认**：每条命令执行前都弹出确认卡片（显示完整命令），用户确认后才在沙箱外执行。
- 文件工具不受影响，仍按软隔离规则执行。
- 界面持续提示当前处于逐条确认模式及其原因。

“绝不悄悄在无沙箱的情况下运行”的原则不变：沙箱外执行只在用户对每一条命令明确确认，或用户主动开启无人值守模式后发生。

### 外部智能体引擎（D72）

Bot 使用外部智能体引擎（Claude Agent / Codex 等，见 [28-external-agents-acp.md](28-external-agents-acp.md)）时，智能体自带的文件与命令工具在其**自身进程与自身沙箱**中运行，不经工具网关的路径检查，也不在 KepCup 沙箱中执行——这是对 D35 / D27 的明确让渡。规则：

- 同样不成立的还有：project `protectRules` 的禁读 / 禁写、Bot 的 `network_policy`、以及「project 以外的读取需授权」——智能体沙箱一般允许全盘只读，只有智能体主动请求权限时才能拦截。
- 智能体的工作目录限定为 project（未绑定则 workspace）；智能体自身沙箱必须开启（Claude 原生沙箱、Codex `workspace-write`），**永不**使用其 bypass / auto / full-access 模式；智能体侧的仓库配置（Claude `.claude/settings.json` 的 hooks 与 allow 规则）不加载。
- 智能体发起的权限请求（ACP `session/request_permission`）由宿主分级：KepCup 自身工具（经宿主 MCP 桥）直接放行、在桥内另走本文的审批；路径先判「工作目录与技能目录」→「应用数据目录其余部分：一律拒绝」→ 常规访问范围；工作目录内按 Bot 的权限档位（只读 / 工作区 / 每次确认）自动放行或拒绝；越界读写走「授权」卡片（审批类型 `agent_tool`，有效期仍为“仅这一次 / 本对话内”）；命令命中只读白名单可放行，否则弹卡且只有“仅这一次”。
- 无人值守模式对 `agent_tool` 自动批准并审计，但与沙箱外执行相同受数据目录底线约束：命令或路径触及应用数据目录（workspace 与技能目录除外）时拒绝。
- 写入租约在 run 开工前显式取得、整个 run 持有，检查点按租约起止前后快照，回退照常可用。（D75：外部智能体只跑任务；只读任务强制 `read_only` 档、不取租约，写任务的租约由任务层在启动前取得。）
- 没有 OS 沙箱的智能体（如 OpenCode）在「工作区」档下工作目录内编辑可放行，但每条命令都弹卡；沙箱不可用的平台（如 Windows 上的 Claude Agent）强制「每次确认」档，等同逐条确认模式。
- Bot 详情持续标示「隔离由外部智能体自身沙箱提供」，并披露读取让渡：智能体自带的联网读取在只读 / 工作区档不逐次确认；部分智能体（如 Codex）的沙箱可不经请求读取整台电脑，包括应用数据目录。
- 只读命令白名单只对智能体能确认「在其自身沙箱内运行」的命令生效；其余命令（包括 Codex 发来的全部命令请求——它只为越出沙箱的命令发请求）一律弹卡，只读档直接拒绝。命令的工作目录位于应用数据目录（workspace 与技能目录除外）时直接拒绝。

## 只读命令白名单

逐条确认模式下，白名单中的命令**无需确认**直接执行。沙箱可用时命令本就无需确认，白名单不起作用。

- 内置默认白名单只包含只读命令，例如 `ls`、`pwd`、`cat`、`head`、`tail`、`wc`、`file`、`stat`、`du`、`tree`、`which`、`grep`、`rg`、`find`，以及 `git status`、`git diff`、`git log`、`git show`。
- 严格匹配，以下情况不豁免：
  - 整条命令中有任何一段不在白名单中（管道、`&&`、`;` 连接的每一段都要命中）
  - 出现写入重定向（`>`、`>>`）、`tee`、命令替换（`$()`、反引号）、后台执行（`&`）、子 shell、变量赋值前缀
  - 带有写入或执行语义的参数，例如 `find -exec`、`find -delete`、`sed -i`、`git -c`
- 白名单不放宽访问范围：命令参数中的路径超出可访问范围时，仍需访问授权。
- 用户可以在设置中查看、增删白名单条目。自定义条目不一定是只读的（例如 `npm test` 会执行项目代码），添加时提示风险由用户承担。

## 无人值守模式

用户不在电脑前时，后台任务不会因等待确认而卡住。

- 开启后，**所有需要用户确认的操作一律自动批准**：访问授权、沙箱外执行、逐条确认模式下的命令、git 远程操作、宿主层环境安装、技能导入、凭据注入、外部智能体的工具权限请求（`agent_tool`，D72）。
- 开启时弹框明确提示这是危险操作，并列出将被自动批准的操作类型（含凭据注入与命令交互输入的无人值守语义，见 [15-interactive-execution.md](15-interactive-execution.md)）；用户确认后生效。
- 凭据申请：本对话内已记住的凭据自动注入使用；没有可用凭据的申请自动拒绝并告知 Bot，绝不挂起。交互模式命令照常执行，无人在场输入时按空闲超时结束。
- 全局开关，可在设置和托盘菜单中切换；开启时可选择“手动关闭”或“N 小时后自动关闭”。
- 底线不变：应用数据目录 `~/.kepcup` 在无人值守模式下仍不可访问。
- **沙箱外命令的自动批准是 fail-closed 的**（D72 安全复核引入，内置与外部智能体同一规则）：命令文本无法可靠证明不触及应用数据目录（`cd` 后接相对路径、引号拼接、通配符、符号链接等都能绕过文本匹配）。因此无人值守下，沙箱外执行的命令（`request_unsandboxed`、逐条确认模式的命令、外部智能体的执行请求）只有同时满足以下条件才自动批准，否则**自动拒绝**并告知 Bot「无人值守下无法确认该命令的安全性」，Bot 可改写为字面命令重试：能完整解析且每个词去引号后为纯字面量（无变量 / 命令替换 / 通配 / 花括号 / `~user`）；不含切换目录或执行上下文的构造（`cd`、`env`、`eval`、`xargs`、各类 shell `-c`、`git -C`、`--chdir` 等）；工作目录不在数据目录内；每个路径按工作目录解析并跟随符号链接后不落在数据目录内。在沙箱内执行的普通命令不受影响。外部智能体（如 Codex）真实写入目标可能与显示路径不同的写入请求，无人值守下一律拒绝。
- 自动批准的访问授权按“仅这一次”处理，模式关闭后不遗留授权。
- MCP 工具调用（`mcp_tool`）在无人值守下**所有风险档**（只读 / 写入 / 破坏性）都自动批准，不拒绝、不排队（D65 修订，borrowings W5）；数据目录底线只作用于命令与路径类审批，不涉及 MCP。审批与审计记录带风险档，执行记录写明「无人值守自动批准（写入 / 破坏性）」；Bot 详情的 MCP 区常驻风险提示（见 [23-mcp-and-subagent.md](23-mcp-and-subagent.md)「风险分级与逐工具策略」）。
- 开启期间窗口顶部显示持续的醒目横幅，托盘图标同步显示状态。
- 自动批准的每一项都记入审计记录（Bot、对话、操作、时间）；用户回来或关闭模式时汇总展示。检查点照常生成，可以回退。

## 系统通知

非无人值守模式下，有待确认的操作且窗口不在前台时，发送系统通知。

## 界面

- 对话中的卡片：授权、沙箱外执行确认、逐条确认模式下的命令确认。
- 右栏显示当前对话中各 Bot 的有效授权列表，可以撤销。
