# 开发指导（How-to）

本目录放**可重复执行的操作指南**：某类工作以后还会反复做，就把做法固定下来，按文档一步步执行。
和另外两个目录的分工：

| 目录 | 回答什么 |
|---|---|
| [../design/](../design/README.md) | 做什么、为什么这样做（决策的权威来源） |
| [../dev/](../dev/README.md) | 怎么实现（工程规范、架构、测试、分阶段计划、进度与偏差） |
| **guides/（本目录）** | **这件事每次怎么做**（操作步骤、检查清单、命令、常见陷阱） |

## 写新指南的约定

- 一份指南只讲一类重复的工作；文件名用动宾短语（`add-xxx.md`），不加序号。
- 开头写清**适用范围**和**前提**；正文用编号步骤，每一步给出：做什么、怎么验证、产出什么。
- 命令要能直接复制执行；涉及环境的坑（例如测试必须在 Docker 里跑）写在对应步骤里，不要另起一节。
- 指南里不重复设计和实现细节，用链接指向 `design/` 与 `dev/`；决策变了先改那边，再改指南。
- 做完一次实际操作后，发现指南和现实不符，**当场修指南**，不要留给下一个人。
