# 对内沟通稿

面向**组织内部读者**的通知与说明文。判断三个变量再动笔：读者范围（全员/部门/项目组）、正式程度（制度级/事务级/氛围级）、渠道（邮件/群/公告栏）。

## 体例选择

| 场景 | 体例 | 语气 |
|---|---|---|
| 制度生效、组织调整、重大变更 | 正式公告 | 严肃、完整、带依据 |
| 例行事务（放假、系统维护、流程切换） | 事务通知 | 清楚、简短、可执行 |
| 活动、庆功、公益动员 | 动员稿 | 有温度、口语一点 |

## 结构模板

```markdown
【标题】{一句话说清什么事}（如：关于 X 系统 10 月 12 日停机升级的通知）

{称呼，如 各位同事：}

一、什么事：{2-3 句讲清事实}
二、影响谁：{具体到人群与场景}
三、需要你做什么：{编号列出，含时间点}
四、背景与原因：{可选，2-3 句}
五、有问题找谁：{联系人/渠道}

{落款：部门} {日期}
```

## 写作标准

- **标题即信息**：读者只看标题就该知道"发生了什么、要不要行动"。
- 行动项三要素：谁、做什么、什么时候前。"近期""尽快"禁止，写具体日期时间。
- 变更通知必须写清：变更前后对比（旧方式 → 新方式）、生效时间、过渡期安排。
- 一个通知只说一件事；多件事拆开发或分节编号。
- 篇幅：事务通知 ≤ 300 字；全员信 ≤ 600 字；超了说明没想清楚。

## 交付流程

1. 先给草稿，标注【待确认】的口径（时间、名单、政策细节），请用户核实。
2. 用户确认后按目标渠道微调：邮件加主题行建议；群发版本可更短、带 @全体。
3. 涉及薪酬、人事变动、绩效等敏感话题：提醒用户此类文稿通常需 HR/法务审核后再发。
