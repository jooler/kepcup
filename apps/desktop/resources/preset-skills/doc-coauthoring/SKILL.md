# 文档协作改稿

与用户**多轮协作**完成一份文档。核心纪律：先对齐骨架再填肉；每一轮只解决一层问题；永远以"读者是谁、读完要做什么"为检验标准。

## 四阶段流程

### 阶段一：对齐（1-2 轮）
动笔前必须拿到三个答案，缺就问：
- **读者与用途**：给谁看？读完希望他做什么（批准/理解/行动）？
- **核心论点**：一句话说清这份文档主张什么。
- **骨架**：给出章节提纲（每节一行说明），用户确认或修改后再写正文。

### 阶段二：分节成稿
- 按确认的提纲逐节写，每节交付后收集反馈再继续；用户赶时间可整篇出，但标注"按节修改不影响其他节"。
- 每节自检：有没有服务核心论点？有没有读者已知的废话？

### 阶段三：批注式修订
- 用户给反馈（自然语言或批注列表）时，先**复述修改点清单**并归类：内容错误 / 结构问题 / 表达问题 / 口径问题。
- 逐条处理；有分歧的（如你认为某节应该删）给出理由，由用户拍板，不要默默照单全收，也不要固执己见。
- 大改（调章节、删论点）先说影响面，确认后执行。

### 阶段四：读者视角验收
交稿前以目标读者的身份通读一遍，回答三个问题并附在交付说明里：
1. 读完我能复述核心主张吗？
2. 我该做的事（批钱/排期/转发）在文中能 10 秒内找到依据吗？
3. 哪里我还会提问？——把这些做成"附录：常见问题"或提前补进正文。

## 修订纪律

- 保留版本感：大改前把上一版存 `草稿名-v{n}.md`，用户反悔可回退。
- 改动最小化：用户只让改第 3 节时，不要顺手重写其他节。
- 每轮交付附"本轮改动摘要"（3-5 条），让用户快速核对。
